# Карта источников: где брать свежую фактуру для постов

Проверено живьём **2026-09-13** из этой песочницы. Где написано «проверено» —
значит был реальный запрос, и в отчёте ниже указано, что вернулось. Где
написано «НЕ ПРОВЕРЕНО» — значит запрос не делался или не прошёл; не выдавайте
это за проверенное.

## Главное разделение: ТЕМА и ФАКТ

Это два разных источника, и путать их — основная ошибка.

| | Источник ТЕМЫ | Источник ФАКТА |
|---|---|---|
| Отвечает на вопрос | «о чём сейчас говорят» | «чем это подтвердить» |
| Примеры | Hacker News, Google Trends, Reddit, Habr, Product Hunt | первоисточник исследования, гос.статистика, официальный релиз, arXiv, документация |
| Что с ним делать | взять повод, найти угол | взять цифру, взять дату |
| Можно ли цитировать в посте | **нет** | да, если это первоисточник и есть дата |

Hacker News с 1200 очками говорит только одно: людям интересно. **Очки — не
подтверждение правды.** Заголовок на HN — чья-то формулировка, иногда прямо
искажающая статью. Факт берётся из статьи, на которую история ссылается, и
проверяется до первоисточника.

Google Trends показывает, что люди ИЩУТ. Это сырой спрос, а не факт, и вообще
не утверждение — в пост он идёт только как повод («сегодня все спрашивают X»).

## Hacker News

**Что даёт:** тему и срез спора в тех-нишах (разработка, ИИ, стартапы,
инфраструктура). Ценнее самой статьи часто ветка комментариев: там лежит
возражение, из которого получается сильный крючок.

**Два API, оба бесплатны и без ключа.**

### 1. Официальный Firebase API — ПРОВЕРЕНО

```
GET https://hacker-news.firebaseio.com/v0/topstories.json
GET https://hacker-news.firebaseio.com/v0/item/<id>.json
```

Проверено 2026-09-13: `topstories.json` вернул массив ID (до 500),
`item/1.json` вернул реальный объект:
`{"by":"pg","id":1,"score":57,"title":"Y Combinator","type":"story",...}`.

Списки: `topstories`, `newstories`, `beststories`, `askstories`,
`showstories`, `jobstories`.

- Ключ: **не нужен**. Регистрация: **не нужна**.
- Цена: бесплатно.
- Лимиты: официально не опубликованы. robots.txt сайта требует
  `Crawl-delay: 30` — на API это формально не распространяется, но долбить
  не надо.
- Обновление: практически в реальном времени.
- Легально: да, публичный официальный API ([условия](https://github.com/HackerNews/API)).

**Ловушка:** топы отдаются СПИСКОМ ID, за каждой историей нужен отдельный
запрос. 100 историй = 100 запросов. В `lib/research/hn.mjs` это решено
пачками по 10 с паузой. Второе: **поиска в этом API нет вообще** — для поиска
нужен Algolia (ниже).

### 2. Algolia HN Search API — ПРОВЕРЕНО

```
GET https://hn.algolia.com/api/v1/search?query=<слова>&tags=story
GET https://hn.algolia.com/api/v1/search_by_date?query=<слова>
   &numericFilters=created_at_i>...,points>=100
```

Проверено 2026-09-13: `?tags=front_page` вернул реальные истории
(«We must pace the frontier», автор apsec112). Поиск `"ai agents"` за 14 дней
с `points>=100` вернул 4 истории, верхняя — «OpenAI agents carried out an
undisclosed attack on RubyGems», 930 очков.

- Ключ: **не нужен**. Цена: бесплатно.
- Лимиты: официально не опубликованы. Пауза между запросами обязательна.
- Легально: публичный API Algolia для HN, на нём работает поиск самого
  news.ycombinator.com.
- Фильтры в `numericFilters`: `created_at_i` (unix-время), `points`,
  `num_comments`. Теги: `story`, `show_hn`, `ask_hn`, `front_page`, `comment`.

**Ловушка:** `search` сортирует по релевантности, а не по дате — для «что
нового» нужен `search_by_date`. И `tags=story` обязателен, иначе в выдачу
лезут комментарии.

**Наш клиент:** `node lib/research/hn.mjs top|search|search-many`.

## Google Trends — ПРОВЕРЕНО, и это лучшая находка без ключа

```
GET https://trends.google.com/trending/rss?geo=RU
```

Проверено 2026-09-13: HTTP 200, ~22 КБ, **без ключа и без регистрации**.
Вернул 10 актуальных запросов с объёмом и, что важнее, с вложенными
новостями. Реальный фрагмент:

```
<title>танкер</title>
<ht:approx_traffic>1000+</ht:approx_traffic>
<ht:news_item>
  <ht:news_item_title>Украина поразила перевозивший подсанкционную нефть
    танкер российского «теневого флота»</ht:news_item_title>
  <ht:news_item_url>https://ru.themoscowtimes.com/2026/09/12/...</ht:news_item_url>
  <ht:news_item_source>Русская служба The Moscow Times</ht:news_item_source>
</ht:news_item>
```

- `geo=`: RU, US, DE, GB и т.д. — по стране.
- Обновление: каждые 10 минут (pubDate шли с шагом 10 мин).
- Цена: бесплатно. Ключ: не нужен.

**Зачем это нам:** `<ht:news_item>` — это готовый ответ на вопрос «почему
сейчас», с конкретными статьями и их изданиями. То есть Trends даёт и тему,
и мостик к фактуре.

**Ловушки (обе поймались живьём и обойдены в коде):**
1. У ВСЕХ записей `<link>` **одинаковый** — адрес самого фида. Дедупликация
   по ссылке схлопнула бы 10 разных трендов в один. В `fetch-feeds.mjs`
   такие записи различаются по заголовку.
2. Издания внутри `ht:news_item` — это чаще всего **перепечатки**
   (региональные новостные сайты). Как источник факта они не годятся: нужно
   идти до того, кого они цитируют.
3. Старый `api/dailytrends` и библиотеки вокруг «pytrends» — не то же самое,
   часто отдают 429. Этот RSS — проверенный путь.

**Альтернативы без ключа:** НЕ ПРОВЕРЕНО. Официального открытого Trends API
нет; всё, что предлагает «Trends API», — сторонние платные обёртки.

## Reddit — ЗДЕСЬ ЛОВУШКА, ЧИТАТЬ ЦЕЛИКОМ

**Технически:** `https://www.reddit.com/r/<sub>/.rss` отдаёт валидный Atom.
Проверено 2026-09-13: HTTP 200, `application/atom+xml`, 27 КБ, свежие записи.

**Юридически: robots.txt запрещает это полностью.** Проверено 2026-09-13,
полный текст `https://www.reddit.com/robots.txt`:

```
# Reddit believes in an open internet, but not the misuse of public content.
# See ... Reddit's Public Content Policy for access and use restrictions
User-agent: *
Disallow: /
```

`old.reddit.com/robots.txt` — то же самое. Исключений для `.rss` **нет**.
То есть автоматический сбор даже публичного RSS противоречит robots.txt и
Public Content Policy, несмотря на код 200.

**Поэтому в `config/sources.example.json` Reddit лежит в `feedsDisabled`, а
не в `feeds`.** Проверено, что защита работает: при попытке включить его
`fetch-feeds.mjs` отвечает
`ПРОПУЩЕН: robots.txt запрещает: Disallow: /`.

**Официальный Reddit Data API** (если Reddit всё же нужен):
- Требует регистрации приложения на reddit.com/prefs/apps и OAuth2.
  Неавторизованные запросы отклоняются.
- Бесплатный тариф: 100 запросов/мин на OAuth-клиент, усреднение по
  10-минутному окну — для **некоммерческого** использования.
- Коммерческое использование: требует **предварительного письменного
  одобрения** Reddit, ревью занимает недели. Цена коммерческого доступа
  порядка $0,24 за 1000 вызовов, крупный тариф — десятки тысяч $/мес.
- Всё это по состоянию на 2026 год, источник — обзоры условий, **не
  проверено живым запросом к API** (нужна регистрация и одобрение).

**Вывод для скила:** без одобрения Reddit — не использовать. Если нужна тема
с Reddit, читать глазами через браузер (человек читает сайт — это не
автоматический сбор) и брать оттуда только повод, а факт проверять в
первоисточнике.

## RSS/Atom вообще — самый надёжный канал, и вот почему

RSS — единственный канал, который **создан для того, чтобы его читали
программы**. Отсюда всё остальное:

- не нужен ключ, не нужна регистрация, нечего «отзывать»;
- издатель сам согласился на машинное чтение, выставив фид;
- формат не меняется годами, в отличие от HTML-вёрстки, которая ломает
  скрейперы при каждом редизайне;
- отдаёт дату публикации в структурированном виде — а дата нам обязательна
  по правилам скила;
- дешёвый: один запрос = 20-50 записей.

### Как искать фиды под нишу владельца

1. Взять 5-10 сайтов, которые ниша реально читает (спросить у владельца, а
   не угадывать).
2. На каждом проверить по очереди:
   `/feed`, `/rss`, `/rss.xml`, `/feed.xml`, `/atom.xml`, `/index.xml`,
   `/blog/feed`, `/news/rss`.
3. Посмотреть в исходнике главной:
   `<link rel="alternate" type="application/rss+xml" href="...">`.
4. У WordPress почти всегда работает `/feed`, у Substack — `/feed`,
   у Ghost — `/rss/`.
5. **Проверить, что пришёл фид, а не HTML** — см. ловушку ниже.

### Ловушка №1, на которой теряют время: HTTP 200 ≠ фид существует

Сервер отдаёт код 200 и HTML-страницу вместо фида. Проверено живьём
2026-09-13:

| Адрес | Код | Что реально пришло |
|---|---|---|
| `https://www.indiehackers.com/feed.xml` | **200** | `<!DOCTYPE html>` — HTML-страница, не фид |
| `https://feeds.feedburner.com/indiehackers` | 404 | мёртв |
| Threads `/@user.rss` | 200 | HTML (см. раздел про Threads) |

Поэтому в `lib/research/fetch-feeds.mjs` перед парсингом проверяется, что в
начале документа есть `<rss`, `<feed` или `<rdf`, и HTML отсекается с
понятным сообщением: «Сервер отдал HTML, а не фид».

### Ловушка №2: robots.txt может запрещать сам фид

Проверено 2026-09-13 на GitHub: `https://github.com/nodejs/node/releases.atom`
отдаёт HTTP 200 и валидный Atom, но в `github.com/robots.txt` есть
`Disallow: /*.atom$`. Наш сборщик это поймал и отказался:
`ПРОПУЩЕН: robots.txt запрещает: Disallow: /*.atom$`.
Для GitHub нужно брать REST API (ниже), а не Atom.

### Ловушка №4: короткое ключевое слово как подстрока даёт мусор

Поймано живьём 2026-09-13. Ниша про искусственный интеллект — ключевое слово
«ии». Как подстрока оно находится в «ситуа**ции**», «коллиз**ии**»,
«расширен**ии**»: из трёх «совпадений» настоящим было одно («ии-агент»).

Поэтому в `fetch-feeds.mjs` фильтр `--include/--exclude` ищет **по границе
слова**, а не по подстроке. Нужен префикс — ставится звёздочка:
`нейросет*` совпадёт с «нейросети» и «нейросетью», а `нейросет` без звёздочки
потребует ровно это слово.

Отдельная тонкость: `\b` в JavaScript **не работает с кириллицей** (она не
входит в `\w`), поэтому граница слова задана вручную через класс букв обоих
алфавитов. Наивное `\bии\b` молча не находит ничего.

### Ловушка №3: даты в Atom врут, если брать не то поле

Проверено на Product Hunt 2026-09-13: в `<published>` стоит дата **создания
продукта** (бывает старше недели), а в фид он попал сегодня — это
`<updated>`. Если предпочитать `published`, вся лента выглядит протухшей:
у нас 50 записей превращались в 0 после фильтра свежести. Исправлено —
берём более позднюю из двух.

## Habr — ПРОВЕРЕНО

```
GET https://habr.com/ru/rss/articles/?fl=ru       # все статьи
GET https://habr.com/ru/rss/hubs/<хаб>/articles/  # по хабу
GET https://habr.com/ru/rss/best/daily/           # лучшее за день
```

Проверено 2026-09-13: HTTP 200, `text/xml`, ~100 КБ. Реальные заголовки:
«Когда atomic действительно быстрее Mutex», «Тернарная нейронка на C#»,
«Агентное будущее» — с датами `Sun, 13 Sep 2026 04:47:59 GMT`.

- Ключ: не нужен. Цена: бесплатно. Обновление: непрерывно.
- Легально: `habr.com/robots.txt` (проверено) содержит правила для Yandex,
  Googlebot, Slurp и запрещает в основном `/search/`, страницы подписчиков и
  utm-адреса. `Disallow: /` для `*` **нет**, запрета на `/rss/` нет.
- **Ловушка:** заголовки внутри `<![CDATA[...]]>` — наивный парсер отдаст
  текст вместе с обёрткой. У нас CDATA снимается. Второе: поток очень шумный
  (все хабы подряд) — фильтруйте `keywordsInclude` под нишу, иначе в ленте
  будет 40 случайных статей.

## GitHub — API ПРОВЕРЕНО, Atom ЗАПРЕЩЁН robots

**Для тех-ниш:** релизы и всплески звёзд — хороший повод («вышла версия X,
вот что меняется»).

```
GET https://api.github.com/repos/<owner>/<repo>/releases?per_page=5
GET https://api.github.com/search/repositories?q=created:>2026-09-06&sort=stars
```

Проверено 2026-09-13 без ключа:
- `/rate_limit` → `"core":{"limit":60,...}` — **60 запросов/час на IP** без
  токена;
- релизы nodejs/node → `v26.8.2 2026-09-09T16:07:48Z`, `v24.21.0
  2026-09-08T21:51:09Z`;
- поиск свежих репозиториев вернул реальные `full_name`.

- С токеном (`GITHUB_TOKEN`, classic/fine-grained, без прав на запись) —
  5000 запросов/час. Токен только через env, в коде его нет.
- **Ловушка:** «GitHub Trending» (`github.com/trending`) — **не API и не
  фид**, это HTML-страница, и в robots.txt она не разрешена. Все
  «trending API» — сторонние скрейперы. Вместо неё —
  `search/repositories` с фильтром по дате создания и звёздам.
- **Ловушка:** `.atom`-фиды (`/releases.atom`, `/commits.atom`) отдают 200,
  но запрещены `Disallow: /*.atom$` — проверено. Берите REST API.
- GitHub robots.txt (проверено) явно перечисляет `ClaudeBot` и `anthropic-ai`
  с `Crawl-delay: 1` и узким списком `Allow:` — то есть на остальное
  согласия нет.

## arXiv — НЕ ПРОВЕРЕНО (получен 429)

```
GET https://export.arxiv.org/api/query?search_query=cat:cs.CL
   &max_results=20&sortBy=submittedDate&sortOrder=descending
```

Проверено 2026-09-13: вернул **HTTP 429 «Rate exceeded»** — почти наверняка
из-за общего IP песочницы, а не из-за нашего запроса. Формат ответа —
Atom, парсится тем же `fetch-feeds.mjs`; лежит в `feedsDisabled`.

- Ключ: не нужен. Цена: бесплатно.
- Правила arXiv: не чаще **одного запроса в 3 секунды**, свой User-Agent
  обязателен.
- Как источник ФАКТА: годится, но с оговоркой — **препринт не прошёл
  рецензирование**. В посте это нужно называть препринтом, а не
  «исследованием показало».

## Wikipedia / Wikidata — для проверки фактов

### Wikipedia API — ПРОВЕРЕНО

```
GET https://ru.wikipedia.org/w/api.php?action=query&prop=extracts
   &exintro&explaintext&format=json&titles=<статья>
GET https://ru.wikipedia.org/api/rest_v1/page/summary/<статья>
```

Проверено 2026-09-13: оба вернули HTTP 200 и реальные данные (статья
«Threads (социальная сеть)», pageid 10268385; summary по «Hacker News» с
`wikibase_item":"Q686797"`).

- Ключ: не нужен. Цена: бесплатно. Легально: да, официальный API.
- Правила: свой User-Agent обязателен (у них есть политика UA), разумный темп.
- **Ключевая ловушка:** Википедия — **НЕ первоисточник**. Она сама об этом
  пишет. Её роль в нашем процессе одна: **быстро найти сноску на
  первоисточник**. Цитировать в посте Википедию нельзя, цитировать нужно то,
  на что она ссылается, и проверять дату там.

### Wikidata SPARQL — ПРОВЕРЕНО (эндпоинт живой)

```
GET https://query.wikidata.org/sparql?query=<SPARQL>  (Accept: application/sparql-results+json)
```

Проверено 2026-09-13: эндпоинт ответил корректным JSON
(`{"head":{"vars":["x"]},"results":{"bindings":[]}}`) — пустой результат,
потому что запрос был с заведомо случайным Q-идентификатором. То есть API
работает, содержательный запрос **НЕ ПРОВЕРЕН**.

- Хорош для сверки дат, чисел и связей (кто кем владеет, когда основано).
- Ловушка: тяжёлые запросы обрываются по таймауту; нужен `LIMIT`.

## Официальные новостные RSS и отраслевые рассылки

**Это лучший источник ФАКТА из массовых.** Логика: брать фид **той
организации, которая является субъектом новости**, а не фид новостного сайта.

- Пресс-центры компаний: `/news/feed`, `/press/rss`, блоги
  (`openai.com/blog/rss.xml`, `about.fb.com/news/feed/` и т.п.) —
  **конкретные адреса НЕ ПРОВЕРЕНЫ**, проверяйте перед добавлением.
- Гос.статистика (Росстат, ЦБ РФ, Eurostat, BLS) — первоисточник по
  определению. **НЕ ПРОВЕРЕНО** в этой сессии.
- Российские новостные RSS: `lenta.ru/rss/news` в этой песочнице **не
  открылся** (соединение не установилось, HTTP 000) — среда, а не источник;
  `rbc.ru` ajax-эндпоинт вернул **403**. Проверять на реальной машине.

**Ловушка отраслевых рассылок:** они почти всегда пересказ. «По данным
исследования X» в рассылке — это перепечатка. Идти в X.

## Чего НЕ делать: Threads

Проверено живьём 2026-09-13, `https://www.threads.com/robots.txt` и
`https://www.threads.net/robots.txt` начинаются буквально так:

```
# Notice: Collection of data on Threads through automated means is
# prohibited unless you have express written permission from Threads
# and may only be conducted for the limited purpose contained in said
# permission.
# All authorized user-agents listed on this page must comply with Meta's
# Automated Data Collection Terms available at:
# https://www.facebook.com/legal/automated_data_collection_terms
User-agent: ClaudeBot
Disallow: /
```

`ClaudeBot`, `GPTBot`, `Google-Extended`, `PerplexityBot`, `Amazonbot` и
другие — `Disallow: /`.

Выводы:
- **скрейпинг Threads запрещён**, в том числе для залогиненных;
- **RSS у Threads не существует**: адрес вида `/@user.rss` отдаёт код 200,
  но это HTML-страница, а не фид — на этом легко обмануться;
- все неофициальные библиотеки Threads мертвы с 2023 года;
- внутри самого Threads легален только официальный
  `GET /v1.0/keyword_search` (лимит 2200 запросов/24 ч, требует App Review).
  Им занимается отдельная часть кита — здесь он не дублируется.

Наша зона — внешние легальные источники, перечисленные выше.

## Гигиена автоматического сбора

Обязательно, и не только из вежливости — так нас не блокируют:

1. **Свой User-Agent с контактом.** `threads-kit-research/1.0
   (+contact: you@example.com)`. Обезличенный UA — первый кандидат на бан.
   **Ловушка, поймана живьём:** HTTP-заголовки принимают только latin-1.
   Кириллица в User-Agent (например, оставленный в шаблоне текст «укажите
   свою почту») роняет **все** запросы с `Cannot convert argument to a
   ByteString`, и отчёт выглядит так, будто лежит весь интернет. В
   `fetch-feeds.mjs` на это стоит отдельная проверка с внятной ошибкой.
2. **robots.txt читать до запроса,** а не после. В `fetch-feeds.mjs` это
   включено по умолчанию (`respectRobots: true`).
3. **Пауза между источниками** (по умолчанию 1,5 с) и уважение
   `Crawl-delay` — у HN он 30 секунд.
4. **Не ходить чаще, чем обновляется источник.** Раз в сутки утром для
   утреннего прохода достаточно; Trends обновляется раз в 10 минут, но нам
   не нужно чаще раза в день.
5. **Кешировать.** Повторный запрос за тем же самым — бессмысленная нагрузка.
6. **Никаких ключей в коде.** Только env (`GITHUB_TOKEN`, `THREADS_KIT_UA`),
   с понятной ошибкой при отсутствии.
