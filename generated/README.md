# generated/

Здесь лежит то, что пойдёт в публикацию, и учёт результатов.

Папка почти целиком в `.gitignore`: ваши черновики и ваша статистика — ваши,
в общий репозиторий они не уезжают. В репозитории остаётся только этот файл,
`tracker.csv` с пустой шапкой и примеры с суффиксом `.example.md`.

## Что тут бывает

- `week-NN-ru.md` / `week-NN-en.md` — недели постов. Каждый пост подписан:
  день, формула, цель, план первого часа.
- `tracker.csv` — учёт публикаций и результатов.

## Перед публикацией

1. **Проверить факты.** Каждая цифра должна иметь источник. Выдуманную цифру
   в Threads разбирают в комментариях за час.
2. **Прогнать линтер:** `node lib/check.mjs generated/week-01-ru.md`
   Код возврата 1 — переписать, не публиковать.
3. **Публиковать, когда есть час на ответы.** Первый час решает охват:
   ответ автора поднимает пост сильнее любого лайка.

## Про tracker.csv

```
дата, время, пост_id, формула, язык, тема,
просмотры, лайки, ответы, репосты, цитаты,
осмысленные_ответы, переходы_в_личку, результат
```

Первая группа — что публиковали. Вторая — что отдал Threads (эти поля
забираются из API автоматически: `views`, `likes`, `replies`, `reposts`,
`quotes`). Третья — то, что API не знает и считаете вы сами.

**Почему лайки записываем, но не смотрим на них.** Лайк почти не влияет на
охват. Смотреть надо на репосты (площадка считает их закладкой) и на ответы.
`осмысленные_ответы` — это не «круто!», а те, где человек рассказал свою
ситуацию: именно они превращаются в результат.

`время` записываем, потому что на своей аудитории час публикации почти всегда
важнее темы, а узнать это можно только по своим данным.

## Когда таблица начнёт приносить пользу

Меньше 10 строк — выводов нет, и инструменты честно об этом скажут
(`node lib/stats.mjs`). После 3–4 недель видно связку «формула × тема × время».
С этого момента план строится по своим данным, а не по общим рекомендациям.
