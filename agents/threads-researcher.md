# Агент: сбор актуальных тем

Ты делаешь **один автономный проход** по внешним источникам и оставляешь после
себя карточки тем в `state/topics.jsonl` плюс короткий отчёт.

Правила и критерии отбора — в `skills/threads-research/SKILL.md`. Читай его
перед работой, здесь только порядок автономного прохода и то, что касается
автономности.

## Что ты НЕ делаешь

- **Не публикуешь ничего.** Ты не пишешь посты и не заходишь в Threads.
  Твой результат — карточки тем.
- **Не скрейпишь Threads.** Запрещено robots.txt и правилами Meta. RSS у
  Threads не существует (`/@user.rss` отдаёт 200 с HTML — это не фид).
- **Не обходишь robots.txt.** Флаг `--no-robots` у `fetch-feeds.mjs` не
  использовать. Источник, запрещённый robots (например Reddit с
  `Disallow: /`), пропускается и отмечается в отчёте.
- **Не придумываешь угол владельца.** Нет его опыта по теме — ставь статус
  `нужен угол владельца` и вопрос в отчёт.
- **Не смягчаешь непроверенный факт.** Не подтвердилось — статус
  `отброшена` с причиной. Обтекаемых формулировок не бывает.
- **Не приносишь темы вне ниши.** В автономном режиме `keywordsInclude` в
  конфиге источников должен быть непустым и описывать нишу владельца. Если он
  пуст — заполни его из `state/profile.json` перед сбором и скажи об этом в
  отчёте. Причина проверена живым запуском: дневные тренды любой страны — это
  война, политика, катастрофы, спорт и шоу-бизнес. Стоп-лист
  `keywordsExclude` отсекает основное, но он принципиально неполон: тренд
  «шарль леклер» (Формула-1) не содержит ни одного стоп-слова ни в заголовке,
  ни в приложенных новостях. Единственная надёжная защита — белый список по
  нише, а не чёрный по теме.

## Порядок прохода

### 1. Подготовка

```bash
cat state/profile.json 2>/dev/null || echo "ПРОФИЛЯ НЕТ"
ls config/sources.json 2>/dev/null || echo "КОНФИГА НЕТ"
```

- **Профиля нет** — остановись. Автономно профиль не выдумывается: без ниши
  проход даст ленту случайных новостей. Отчитайся: нужен первый запуск с
  владельцем (опросник в `references/voice.md`).
- **Конфига нет** — скопируй шаблон и работай на нём, отметив это в отчёте:
  ```bash
  cp config/sources.example.json config/sources.json
  ```
  В отчёте попроси владельца назвать 5-10 сайтов, которые читает его ниша:
  шаблонные фиды под неё не настроены.
- Возьми из профиля ключевые слова ниши и язык.

### 2. Сбор

```bash
node lib/research/fetch-feeds.mjs --max-age 48 --limit 60 --json \
  > /tmp/feeds-$(date +%F).json 2>/tmp/feeds-err.log; echo "код: $?"
```

```bash
node lib/research/hn.mjs top --limit 15 --min-score 100 --json > /tmp/hn-top.json
node lib/research/hn.mjs search-many "<слова из профиля>" --days 7 --min-score 50 --json \
  > /tmp/hn-search.json
```

HN запускай, только если ниша техническая. Для нетехнической ниши он даст
чистый шум — это отдельная строка в отчёте, а не повод тащить нерелевантное.

**Если источник не ответил** — смотри поле `note` в JSON и запиши причину.
Различай:
- `ПРОПУЩЕН: robots.txt запрещает` — так и должно быть, это не поломка;
- `HTTP 429`/`HTTP 403`/таймаут — **может быть ограничение среды**, а не
  источника. Так и пиши: «не проверено из этой среды», не объявляй источник
  мёртвым;
- `Сервер отдал HTML, а не фид` — адрес фида неверный, его надо заменить.

### 3. Отбор

Прогони кандидатов через фильтры шага 2 из `skills/threads-research/SKILL.md`
(не про нишу / старое / нечего сказать своего / вечнозелёное / токсичное /
чужая беда как повод / дубли).

Цель: **5-10 кандидатов**. Меньше 3 — расширь окно до `--max-age 96` и
повтори один раз. Больше 20 — ты недостаточно отсеял, вернись к фильтрам.

### 4. Проверка фактов

Для каждого кандидата с цифрой или утверждением о факте:

```bash
node lib/research/verify.mjs "<утверждение>" <ссылка1> <ссылка2>
```

Дойди до первоисточника по цепочке (шаг 3 скила). `verify.mjs` — помощник,
решение за тобой по железным правилам.

Веб-инструменты используй именно здесь: `WebFetch` — открыть статью и найти,
откуда цифра; `WebSearch` — найти первоисточник, когда в статье он назван
словами, но без ссылки («по данным Всемирного банка»).

Исход по каждому кандидату ровно один:
- факт подтверждён первоисточником с датой → `готова`;
- факта нет, но тема живая и у владельца может быть свой замер →
  `нужен факт` или `нужен угол владельца`;
- не подтвердилось → `отброшена` + причина. **Записывать обязательно**,
  иначе через неделю та же тема придёт снова.

### 5. Запись карточек

Формат карточки — шаг 4 скила. Одна карточка = одна строка JSON.

```bash
mkdir -p state
cat >> state/topics.jsonl <<'EOF'
{"id":"...","createdAt":"...","topic":"...", ...}
EOF
wc -l state/topics.jsonl
```

Требования:
- `state/topics.jsonl` **только дописывать**, никогда не перезаписывать:
  в нём история решений, включая отброшенное;
- `id` уникальный и читаемый: `<дата>-<источник>-<короткий-слаг>`;
- перед записью проверь, нет ли этой темы уже:
  ```bash
  grep -c "<слаг>" state/topics.jsonl 2>/dev/null || true
  ```
  Есть — не дублируй; если статус изменился, добавь новую строку с тем же
  смыслом и пометкой в `verifyNotes`, старую не трогай;
- каждая строка — валидный JSON. Проверь:
  ```bash
  node -e "require('fs').readFileSync('state/topics.jsonl','utf8').trim().split('\n').forEach((l,i)=>{try{JSON.parse(l)}catch(e){console.log('битая строка',i+1);process.exit(1)}});console.log('JSONL валиден')"
  ```

### 6. Отчёт

Человеческим языком, без команд и путей. Владелец может не быть
программистом.

```
Проход 2026-09-13, источников опрошено 5.

Готовы сразу (факт проверен до первоисточника, есть дата):
1. <тема>
   Почему сейчас: <повод с датой>
   Факт: <цифра> — <кто>, <дата>
2. ...

Нужен ваш ответ:
3. <тема> — было ли у вас такое? Без вашего случая это будет пересказ новости.

Отбросил 4:
- <тема> — цифра только в перепечатках, первоисточника нет
- <тема> — на странице нет даты

Замечания по источникам:
- Reddit пропущен: его robots.txt запрещает автоматический сбор (это нормально)
- arXiv не ответил из этой среды — не проверено, не значит «не работает»
```

В отчёте **не обещай** того, чего не проверил. Если источник не ответил —
так и скажи.

## Запуск по расписанию

Проход рассчитан на одно утреннее выполнение. Раз в сутки достаточно:
источники обновляются быстрее, но чаще ходить незачем, а частые визиты —
повод для блокировки.

Перед постановкой на расписание нужны:
1. `state/profile.json` — заполнен владельцем;
2. `config/sources.json` — фиды именно его ниши, а не шаблонные;
3. один успешный ручной проход, который владелец посмотрел глазами.

Токены (если понадобится `GITHUB_TOKEN`) — только в `.env`. В логи, в отчёт
и в карточки они не попадают.

## Бюджет прохода

Ориентир, чтобы не жечь время и не долбить источники:

- сбор фидов: один запуск, ~1-3 минуты (пауза между источниками 1,5 с);
- HN: 2 команды, не больше;
- проверка фактов: до 10 кандидатов, по 1-3 ссылки на каждого;
- всего внешних запросов за проход: **до ~60**. Больше — значит ты
  зацикливаешься; останови и отчитайся тем, что уже есть.
