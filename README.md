# threads-kit

Набор скилов для Claude Code: писать посты в Threads, находить актуальные темы,
следить за чужими ветками и отвечать в них, разбирать свою статистику.

**Программировать не нужно.** Вы говорите Клоду словами, что хотите получить,
он запускает нужные инструменты сам. Все команды в этом файле — для Клода,
не для вас: можно просто показать ему нужный раздел.

---

## С чего начать

```
git clone https://github.com/DevGreenBox/threads-kit
cd threads-kit
```

Дальше откройте Claude Code в этой папке и скажите:

> Прочитай CLAUDE.md и настрой меня. Моя ниша — <опишите своими словами>.

Клод задаст 10 вопросов про вашу нишу, аудиторию и то, чем вы можете
подтвердить свою компетентность, и сложит ответы в профиль. **Пока профиля нет,
посты не пишутся** — иначе получится безликий текст, который не отличить от
тысячи других.

Из всех вопросов главный — третий: **банк фактов.** Ваши цифры, случаи из
работы, замеры, «было → стало». Без него набор работать не будет, и это
сделано намеренно: в Threads пост живёт в комментариях, и выдуманный кейс
разбирают за час.

Ничего больше настраивать не нужно — писать посты можно сразу. Доступ к API
(следующий раздел) нужен только для автоматизации: мониторинга чужих веток и
автоматического сбора статистики.

## Что здесь есть

| Что | Куда смотреть | Нужен ли доступ к API |
|---|---|---|
| Написать пост | `skills/threads-post/` | нет |
| Написать тред | `skills/threads-thread/` | нет |
| Найти актуальные темы и проверить факты | `skills/threads-research/` | нет |
| Проверить готовый пост перед публикацией | `lib/check.mjs` | нет |
| Утренний автономный сбор тем | `agents/threads-researcher.md` | нет |
| Следить за чужими ветками и отвечать | `agents/threads-monitor.md` | **да** |
| Недельный разбор своих результатов | `agents/threads-analyst.md` | да (или руками) |

Скажите Клоду «напиши пост про X» — он подберёт формулу крючка из 11
доступных, напишет, вычистит следы ИИ, прогонит через линтер и отдаст черновик
с планом первого часа.

## Автоматизация: что разрешено, а что нет

Важное, что стоит знать до того, как строить планы.

**Разрешено официальным API Meta** (нужна заявка на App Review, 1–3 недели):
искать по чужим публичным постам (2200 запросов в сутки), отвечать в чужие
ветки, публиковать свои посты (250 в сутки), читать свою статистику.

**Запрещено и не поддерживается:** скрейпинг Threads (прямо запрещён его
`robots.txt` и правилами Meta, в том числе для залогиненных), неофициальные
библиотеки (все мертвы с 2023 года), чужая статистика. RSS у Threads **не
существует** — адрес вида `/@user.rss` отдаёт код 200, но это HTML-страница,
а не фид; на этом легко обмануться.

Подробно, со ссылками на документацию: `docs/api-facts.md`.
Как получить доступ, по шагам: `config/README.md`.

### Про риск блокировки

Главная опасность не юридическая, а поведенческая: Threads блокирует за
**похожие ответы разным людям**. Поэтому в наборе зашиты предохранители,
которые нельзя отключить правкой конфига:

- потолок **40 ответов в сутки** (жёсткий предел 80) там, где API разрешает 1000;
- проверка непохожести каждого ответа на всё отправленное ранее;
- минимум 10 минут между ответами со случайным разбросом, ночная пауза;
- один ответ в одну ветку, не больше одного ответа автору в неделю;
- стоп-кран: при первом признаке блокировки вся активность останавливается
  и возобновляется только вручную.

Попытка выставить в конфиге 5000 ответов в сутки молча превратится в 80.
Это сделано специально: аккаунт — единственный невосстановимый актив.

## Как проверяется качество

Любой пост перед публикацией проходит линтер:

```
node lib/check.mjs generated/week-01-ru.md
```

Он ловит маркеры ИИ, канцелярит, мёртвые фразы, приманки на вовлечение,
превышение 500 символов, лишние хэштеги и ссылку в первом посте. Код возврата
1 — переписать, не публиковать. Линтер проверяет **форму, а не правду**: он не
знает, настоящая ли ваша цифра. За факты отвечает человек.

## Что важно знать про площадку

- Лайк почти ничего не весит. Репост Threads считает закладкой, а **ответ
  весит больше всего** — поэтому пост проектируется под разговор.
- Ссылка в первом посте режет охват. Ссылка идёт в ответ на свой же пост.
- Первый час решает: публикуйте, когда есть время отвечать.
- Один хэштег максимум, второй платформа отклоняет. 500 символов.
- Правило «писать строчными» относится **только к английскому**. По-русски это
  читается как неграмотность.

Полностью, с пометками где официальные данные, а где замеры сообщества:
`references/algorithm.md`.

## Что остаётся вашим

В общий репозиторий не уезжают: токен (`.env`), ваш профиль и рабочее
состояние (`state/`), ваши черновики и статистика (`generated/`), ваши
приватные факты (`private/`). Всё это в `.gitignore` — данные конкретного
человека не смешиваются с инструментом.

## Структура

```
skills/      скилы: пост, тред, поиск тем
agents/      автономные агенты: сбор тем, мониторинг веток, аналитик
references/  формулы крючков, разбор алгоритма, настройка голоса, источники
lib/         инструменты: линтер, метрики, статистика, API, предохранители
config/      примеры конфигов и пошаговая инструкция по доступу к API
docs/        проверенные факты об API Threads
generated/   ваши посты и трекер результатов
state/       профиль, очереди, журнал действий
```

линтер, предохранители и агенты написаны заново.
