# Threads API: проверенные факты

Дата проверки: **13 сентября 2026**. Ключевые числа сверены с живой
документацией Meta в этот день.

## Зачем этот файл

Чтобы никто — ни человек, ни Клод в новой сессии — не выдумывал
возможности, которых у API нет. Threads API маленький и сильно ограниченный.
Вокруг него много устаревших статей и мёртвых библиотек, из которых легко
сделать вывод «так можно». Нельзя.

**Правило: если возможности нет в этом файле — считать, что её нет.**
Прежде чем реализовывать что-то за пределами списка ниже, свериться с
`developers.facebook.com/docs/threads` и дописать сюда с датой проверки.

---

## Базовое

| Что | Значение |
|---|---|
| База API | `https://graph.threads.net/v1.0/` |
| Стоимость | бесплатно |
| Формат | REST, JSON, токен в заголовке `Authorization: Bearer` или параметре `access_token` |
| Обязательный скоуп для всего | `threads_basic` |
| **Всё требует App Review** | без одобрения скоупов работает только на своём аккаунте |
| Отзыв доступа | **при неиспользовании 28 дней** доступ к API отзывается |

Последняя строка — не мелочь. Если автоматика простояла месяц, токен
перестанет работать не из-за ошибки в коде.

## Что РАЗРЕШЕНО официально

### 1. Поиск по чужим публичным постам

`GET /v1.0/keyword_search`
Документация: <https://developers.facebook.com/docs/threads/keyword-search>

| Параметр | Значения |
|---|---|
| `q` | поисковая фраза (обязателен) |
| `search_mode` | `KEYWORD` (по умолчанию) или `TAG` |
| `search_type` | `TOP` (по умолчанию) или `RECENT` |
| `media_type` | `TEXT`, `IMAGE`, `VIDEO`; без параметра — все |
| `since` | unix-время, **не раньше 1688540400** (05.07.2023), должно быть меньше `until` |
| `until` | unix-время, не больше текущего |
| `author_username` | точное совпадение ника без `@` |
| `limit` | 1–100, по умолчанию 25 |

- **Лимит: 2200 запросов в скользящем окне 24 часа.**
- **Запросы с пустым результатом квоту НЕ тратят.** Отсюда в коде расход
  отмечается только при непустом ответе (`lib/monitor/api.mjs`).
- Скоуп: `threads_keyword_search`.
- ⚠️ **Без одобрения скоупа поиск идёт только по СВОИМ постам.** Ответ при этом
  формально валиден — отличить «скоуп не дали» от «ничего не нашлось» по
  ответу невозможно. Проверяется глазами один раз после App Review.
- ⚠️ Поле `owner` из ответов **вырезано** Meta.
- ⚠️ Ключевые слова, признанные Meta чувствительными или оскорбительными,
  возвращают **пустой массив без ошибки**.

### 2. Ответ на ЧУЖОЙ пост

Двухшаговая модель:

1. `POST /me/threads` с `media_type=TEXT`, `text`, `reply_to_id` → `creation_id`
2. `POST /me/threads_publish` с `creation_id` → id опубликованного ответа

Разрешено, если вы владелец корневого поста **либо** одобрен скоуп
`threads_keyword_search` / `threads_manage_mentions`.

Автор поста может ограничить круг отвечающих параметром `reply_control`
(все / кого он читает / только упомянутые / только автор / подписчики) —
то есть отказ в ответе может быть настройкой автора, а не ошибкой у нас.

### 3. Публикация своих постов

Та же двухшаговая модель без `reply_to_id`. Скоуп `threads_content_publish`.

### 4. Лимиты публикации

`GET /{threads-user-id}/threads_publishing_limit`, окно 86400 секунд.
Поля: `quota_usage`, `config`, `reply_quota_usage`, `reply_config`,
`delete_quota_usage`, `delete_config`.

| Действие | Лимит за 24 ч |
|---|---|
| Посты | **250** (подтверждено в документации Meta 13.09.2026) |
| Ответы | 1000 |
| Удаления | 100 |

⚠️ Числа по ответам и удалениям на странице публикации постов 13.09.2026
не отображались — сверьте их живым вызовом `threads_publishing_limit` на своём
аккаунте после App Review и, если расходятся, поправьте здесь и в
`ЛИМИТЫ_API` (`lib/monitor/api.mjs`).

**Ответ этого эндпоинта — источник истины.** Локальный счётчик в
`state/quota.json` — только оценка: API не отдаёт остаток по keyword_search,
поэтому его приходится считать самому. При расхождении верить API.

### 5. Свои метрики

Скоуп `threads_manage_insights`.

- По посту: `views`, `likes`, `replies`, `reposts`, `quotes`, `shares`
- По аккаунту: то же + `clicks`, `followers_count`, `follower_demographics`
  (демография требует **≥100 подписчиков**)

⚠️ `since`/`until` **не работают для дат раньше 13.04.2024** — в коде это
проверяется до запроса и даёт внятную ошибку.
⚠️ Вложенные ответы в метрики не попадают.
⚠️ **Чужие метрики недоступны в принципе.** Это не обходится.

### 6. Чтение и модерация ответов к своим постам

- `GET /{threads-media-id}/replies` — ответы к посту
- `GET /{threads-user-id}/replies` — все свои ответы
- Поля: `is_reply`, `replied_to`, `root_post`, `reply_audience`,
  `reply_approval_status`
- Модерация: `POST /{id}/manage_reply` (скрыть/показать),
  `GET /{id}/pending_replies`, `POST /{id}/manage_pending_reply`

### 7. Упоминания

Только **вебхуки** (`threads_manage_mentions`).
**Polling-эндпоинта для упоминаний НЕ существует** — периодически опрашивать
упоминания нечем. Нужны упоминания — нужен публичный HTTPS-адрес под вебхук.

## Что ЗАПРЕЩЕНО и почему

Ничего из этого списка не реализовывать ни в каком виде — даже «только
для теста», даже «один раз посмотреть».

| Запрещено | Почему |
|---|---|
| **Скрейпинг страниц Threads** | `robots.txt` запрещает прямым текстом |
| **Приватное (внутреннее) API** | то же плюс нарушение условий использования |
| **Автосбор данных в залогиненном виде** | Automated Data Collection Terms действуют с 01.01.2025 **и для залогиненных пользователей** — «я же вошёл под собой» не оправдание |
| **Неофициальные библиотеки** | все умерли в 2023, работают через приватное API, то есть через нарушение |
| **RSS-ленты** | **не существуют.** `/@user.rss` отдаёт HTTP 200 с HTML — это ловушка: код «работает», парсит мусор и однажды поймает бан |
| **Чужие метрики** | API их не отдаёт; получить можно только скрейпингом, см. выше |
| **Автофоллоу / автолайк** | массовое автодействие = прямой признак неаутентичного поведения |
| **Обход rate limit** (несколько токенов, прокси, ретраи в обход) | самый быстрый способ потерять аккаунт и приложение целиком |

## 🔴 Поведенческий риск бана

**Главный риск здесь не юридический, а поведенческий.** Meta не подаёт в суд
за лишний запрос — она банит. И банят чаще не за нарушение правил API, а за
то, как выглядит поведение аккаунта.

### За что банят на самом деле

Threads помечает как **inauthentic behavior**:

1. **Повтор похожих ответов у разных авторов.** Главный признак. Не важно,
   что текст технически разный — если это одна мысль, перефразированная
   пять раз, площадка это видит.
2. **Массовые автодействия** ровным ритмом.
3. **Шаблонные комментарии** («Отличный кейс!», «Согласен», «Полезно»).
4. **Активность круглые сутки** без сна.
5. **Повторные приходы к одному автору** — читается как преследование.

### Эскалация

```
rate limit  →  action block  →  блокировка аккаунта
```

Первая ступень обратима и почти безвредна. Вторая — предупреждение, которое
надо воспринимать всерьёз. Третья необратима: аккаунт с историей и
подписчиками восстановить нечем, а новый начинает с нуля и под подозрением.

### Что из этого следует для кода

Владелец хочет полную автоматизацию — она сделана. Но каждая мера ниже
существует именно из-за этого раздела, а не «на всякий случай»:

| Мера | Против чего | Где |
|---|---|---|
| Потолок 40–80 ответов вместо 1000 | массовость | `ЖЁСТКИЙ_МАКСИМУМ` |
| Детектор похожести (4 метрики) | признак №1 | `схожесть()` |
| Интервал 10+ минут **с разбросом** | ровный ритм | `зафиксироватьОтправку()` |
| Ночная пауза по таймзоне | активность без сна | проверка `НОЧЬ` |
| 1 ответ автору в неделю | преследование | проверка `ЛИМИТ_АВТОРА` |
| 1 ответ в ветку | спор и спам | проверка `ЛИМИТ_ВЕТКИ` |
| Минимальная длина ответа | шаблонность | проверка `КОРОТКО` |
| Стоп-кран на любой странный ответ API | эскалация | `опуститьСтопКран()` |

Пороги специально стоят на уровне **5–10% от разрешённого площадкой**, и
поднять их правкой конфига нельзя — только правкой `ЖЁСТКИЙ_МАКСИМУМ` в
`lib/monitor/guardrails.mjs`. Это сознательное неудобство: конфиг правят в
спешке, а аккаунт один.

### Правило, которое важнее всех настроек

**Ответ должен быть полезен читателю, даже если он никогда к нам не
перейдёт.** Автоматика может соблюсти лимиты и всё равно выглядеть спамом,
если ответы пустые. Никакие предохранители не спасут аккаунт, который пишет
осмысленно выглядящий, но бесполезный текст. Содержание — в
`agents/threads-monitor.md`.
