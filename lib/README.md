# lib/ — инструменты

Скрипты на чистом Node.js. **Зависимостей нет**: ни `npm install`,
ни `package.json`. Нужен только установленный Node (проверено на v24).

Запускать можно из любой папки, пути к файлам — любые.

### Работа с текстом и своими цифрами — в сеть не ходят

| скрипт | что делает | код 1 означает |
|---|---|---|
| `check.mjs` | линтер: проверяет пост перед публикацией | пост надо переписать |
| `parse-export.mjs` | разбирает метрики, которые вы выгрузили сами | метрик в файле не нашлось |
| `stats.mjs` | считает по трекеру, какая связка работает | в трекере нет заполненных строк |

### Сбор актуальной информации — ходят во внешние источники

| скрипт | что делает |
|---|---|
| `research/fetch-feeds.mjs` | собирает свежее из RSS: Хабр, Dev.to, Product Hunt, Google Trends |
| `research/hn.mjs` | Hacker News: топ за период и поиск по словам (без ключа) |
| `research/verify.mjs` | помогает проверить факт до первоисточника |

Подробно об источниках, их правилах и ловушках — `references/research-sources.md`.
Скриптам нужна переменная `THREADS_KIT_UA` с вашим контактом: это требование
вежливости к источникам. **Только латиница** — в HTTP-заголовок кириллица не
пролезает, и все источники разом ответят ошибкой.

### Threads API — ходят в Threads по официальному API

| скрипт | что делает |
|---|---|
| `monitor/api.mjs` | клиент API: поиск, публикация, ответы, статистика |
| `monitor/guardrails.mjs` | предохранители: потолки, непохожесть ответов, ритм, стоп-кран |
| `monitor/monitor.mjs` | цикл мониторинга: поиск веток, фильтры, очередь кандидатов |
| `env.mjs` | чтение `.env` (Node сам такие файлы не читает) |

Первые два — библиотеки, но запуск напрямую у них тоже осмысленный:

```bash
node lib/monitor/guardrails.mjs              # самопроверка защит, без сети
node lib/monitor/guardrails.mjs --состояние  # опущен ли стоп-кран, расход за сутки
node lib/monitor/api.mjs                     # работает ли токен и какие скоупы выданы
```

Нужен токен в `.env` и одобренная заявка App Review. Пошагово —
`config/README.md`. Что API разрешает и запрещает — `docs/api-facts.md`.

Коды возврата у всех одинаковые по смыслу:
**0** — всё в порядке, **1** — содержательная проблема (см. таблицу),
**2** — ошибка запуска: файла нет, аргумент не тот, файл битый.

У каждого скрипта есть `--help` по-русски. Запуск без аргументов
не ломается, а объясняет, что подать на вход.

## Граница, которую не пересекает ни один скрипт

В Threads мы ходим **только через официальный API** и только с одобренными
разрешениями. Ни один скрипт здесь:

- не логинится в Threads паролем и не открывает браузер;
- не скрейпит страницы Threads и не трогает его внутренний API;
- не обходит `robots.txt` и не притворяется человеком в браузере.

Это не осторожность, а требование правил Meta: автоматический сбор данных
запрещён прямым текстом в `robots.txt` Threads, в том числе для залогиненных.
Все неофициальные библиотеки мертвы с 2023 года, RSS у Threads не существует.
Подробно — `docs/api-facts.md`.

**Три скрипта из первой таблицы в сеть не ходят вовсе** — ни `check.mjs`, ни
`parse-export.mjs`, ни `stats.mjs`. Они работают только с текстом и цифрами,
которые вы дали им сами: файлом или вставкой. Цифры можно и переписать из
приложения руками (свой профиль → Статистика → пост) — так статистика
работает без всякой заявки в Meta.

## 1. `check.mjs` — линтер постов

Проверяет **форму**: лимиты площадки и признаки машинного текста.
**Не проверяет правду**: настоящая ли цифра в посте, знает только автор.

```bash
node lib/check.mjs generated/week-01-ru.md      # проверить файл
node lib/check.mjs черновик.md --json           # результат машинно
cat пост.txt | node lib/check.mjs               # проверить вставку
node lib/check.mjs --help
```

### Что подать на вход

**Файл-план** — как в `generated/`: посты разделены строкой `---`,
публикуемый текст каждого лежит в ```-блоке.

> **Важно.** Если в файле есть хотя бы один ```-блок, проверяется **только
> содержимое блоков**. Шапка файла, заголовки вида `## ПН — F1` и пометки
> для себя отбрасываются: они не публикуются, поэтому и проверять их нельзя
> (иначе тире из заголовка считается частью поста, а длина завышается).
> Сколько блоков отброшено, скрипт скажет отдельной строкой — чтобы пост,
> забытый без ```, не прошёл мимо проверки незамеченным.

**Одиночный черновик** — просто текст поста, без блоков. Тогда проверяется
весь текст; frontmatter и markdown-заголовки срезаются.

### Два уровня замечаний

- **БЛОКИРУЮЩЕЕ** — нарушен лимит площадки или гарантированный вред
  (ссылка в первом посте, два хэштега, приветствие в начале, вводная вода,
  3+ маркера ИИ). Код возврата 1: пост не отдавать, переписать.
- **ПРЕДУПРЕЖДЕНИЕ** — вероятная проблема, решение за автором
  (нет цифры, нет крючка, много эмодзи, канцелярит).

### Проверка на охват

Дополнительно к лимитам линтер смотрит первую строку — лента показывает
только её:

- есть ли **крючок**: вопрос, цифра, противоречие или названная проблема;
- не начинается ли пост с **вводной воды** («в современном мире»,
  «сегодня хочу рассказать») — это блокирующее: первая строка потрачена
  на разгон.

### Свои правила: `config/voice.json`

Файл **необязателен** — без него работают правила по умолчанию.
Лежит в корне репозитория рядом с `lib/`, путь можно задать явно:
`--config путь/к/voice.json`.

```json
{
  "lang": "ru",
  "forbiddenWords": ["дедлайн", "кейс"],
  "stopPhrases": ["мы лидеры рынка"],
  "warnWords": ["решение"],
  "extraMarkers": ["синергия"],
  "allowMarkers": ["позволяет"],
  "limit": 500,
  "maxEmoji": 2,
  "maxDashes": 2,
  "maxHashtags": 1,
  "firstLineMax": 120,
  "requireHook": true
}
```

Все поля необязательны:

- `lang` — `ru`, `en` или `auto` (по умолчанию определяется по тексту);
- `forbiddenWords`, `stopPhrases` — ваши слова и фразы, **блокирующее**;
- `warnWords` — мягкий список, только предупреждение;
- `extraMarkers` / `allowMarkers` — добавить или снять маркер ИИ
  (`allowMarkers` нужен, если слово из общего списка для вас нормальное);
- остальное — пороги.

Битый JSON или неверный тип поля не молчат: скрипт скажет, какое поле
и что в нём не так, и вернёт код 2.

## 2. `parse-export.mjs` — разбор своих метрик

На выходе: таблица в терминал и, по желанию, markdown-отчёт.
Считает, **какие посты дали охват, какие дали ответы, какая формула сработала**.

```bash
node lib/parse-export.mjs insights.json
node lib/parse-export.mjs metrics.csv --md отчёт.md
node lib/parse-export.mjs вставка.txt --json
cat вставка.txt | node lib/parse-export.mjs
```

### Три формата входа — подойдёт любой

**1. JSON официального Threads API** (`/{media-id}/insights`, метрики
`views,likes,replies,reposts,quotes`). Понимаются все формы, в которых
Meta отдаёт числа:

```json
{"data":[{"name":"views","period":"lifetime","values":[{"value":1234}]}]}
{"data":[{"name":"likes","total_value":{"value":143}}]}
{"data":[{"id":"1","text":"...","views":1234,"likes":10,"replies":5}]}
```

Поля `id` / `text` / `permalink` / `timestamp` подхватываются как подпись
поста, а `formula` / `topic` / `lang` — как разметка для сравнения.
Дневные срезы `views` суммируются.

**2. CSV или таблица, вставленная руками.** Разделитель запятая, точка
с запятой или таб; кавычки для полей с запятыми работают. Названия колонок
понимаются по-русски:

```csv
дата,пост,формула,тема,охват,лайки,ответы,репосты,цитаты
2026-09-01,"474 товара невидимы: 965 байт",F1,SEO,7400,96,41,22,3
```

Минимум: чем пост назвать + колонка охвата.

**3. Свободная вставка**, построчно. Числа с пометками вытаскиваются
в любом порядке, `12 500`, `12,500` и `8.9K` понимаются:

```
474 товара невидимы — 12 500 просмотров, 41 ответ, 22 репоста, 96 лайков
Робот видел Disallow полгода: 8.9K просмотров, 61 ответ, 38 репостов
```

Строки без метрик пропускаются, их количество и номера выводятся.

### Что считается

Кроме сырых цифр — **ER%** и **взвешенный сигнал**:
`ответ×3 + репост×2 + цитата×2 + лайк×0.2`. Веса из `references/algorithm.md`:
на этой площадке лайк почти ничего не значит, ответ значит почти всё.
Поэтому пост с меньшим охватом, но живым обсуждением стоит в рейтинге выше.

Если в данных размечены `формула` / `тема` / `язык`, добавляется срез
«что сработало» с медианами по группам. Где в группе меньше 3 постов,
об этом написано прямо: **наблюдение, а не вывод**.

## 3. `stats.mjs` — анализ своего трекера

Отвечает на один вопрос: **какая связка «формула × тема × время» работает**.
И честно отказывается отвечать, когда данных мало.

```bash
node lib/stats.mjs generated/tracker.csv
node lib/stats.mjs generated/tracker.csv --metric комментарии
node lib/stats.mjs generated/tracker.csv --md отчёт.md
node lib/stats.mjs generated/tracker.csv --min 20
node lib/stats.mjs generated/tracker.csv --json
```

### Формат трекера

Первая строка — шапка. Порядок колонок любой, лишние игнорируются,
названия понимаются по-русски и по-английски:

```csv
дата,пост,формула,язык,тема,охват,комментарии,переходы_в_личку,диагностики,заявки
2026-09-01 09:12,474 товара невидимы,F1,ru,SEO,7400,41,6,2,1
```

Рабочий минимум: **дата + одна колонка результата**.

Дата понимается как `2026-09-01`, `2026-09-01 09:12`, `2026-09-01T09:12`
и `01.09.2026 09:12`. **Если в дате есть часы**, скрипт сам посчитает
день недели и слот (утро / день / вечер / поздний вечер) — это и есть
«время публикации». Часов нет — срез по времени не строится, а не
выдумывается.

### Что на выходе

- медиана выбранной метрики по всем постам, разброс от и до;
- срезы по формуле, теме, языку, времени публикации и дню недели;
- связки **формула × тема**, **формула × время**, **формула × тема × время**;
- один вывод в конце: какая связка лучшая — или почему его нет.

Метрика выбирается автоматически (охват, если он есть), сменить —
`--metric комментарии` / `заявки` / `переходы_в_личку`.
Сравнение идёт по **медиане, а не по среднему**: один залетевший пост
тянет среднее и создаёт ложную картину роста.

### Почему он отказывается делать выводы

Три порога, и все три намеренные:

| порог | значение | смысл |
|---|---|---|
| строк в трекере | 10 | меньше — лучшая связка **не называется вообще** |
| постов в группе | 3 | группа меньше 3 не сравнивается с другими |
| постов в связке | 3 | связка меньше 3 помечается «наблюдение, не вывод» |

На четырёх постах скрипт покажет цифры, но в конце скажет:
«данных мало, лучшую связку не называю, опубликуйте ещё 6 постов
и запустите разбор снова». Это не недоработка: вывод из трёх постов
вреднее, чем его отсутствие, потому что по нему начнут писать все
следующие посты.

Порог можно поднять (`--min 20`), но не опустить ниже 1.

Пустой трекер (только шапка) — не ошибка формата: скрипт вернёт код 1
и скажет, что для только что созданного трекера это нормально.

## Типичный порядок работы

```bash
# 1. Проверить черновик перед публикацией
node lib/check.mjs generated/week-03-ru.md
#    код 1 → переписать; код 0 → можно публиковать

# 2. Через несколько дней внести цифры в трекер руками,
#    затем посмотреть, что сработало
node lib/stats.mjs generated/tracker.csv

# 3. Если выгрузили метрики из API или скопировали из приложения
node lib/parse-export.mjs insights.json --md generated/разбор.md
```

## 4. `monitor/guardrails.mjs` — предохранители

Через них проходит **каждая** отправка. Запущенные напрямую, они не молчат.

### Самопроверка: убедиться, что защита жива

```bash
node lib/monitor/guardrails.mjs
```

Прогоняет двенадцать проверок на выдуманных данных во временной папке:
в сеть ничего не уходит, ваше состояние не трогается. Проверяется главное —
что защиту **нельзя обойти правкой конфига**: запрос 5000 ответов в сутки
превращается в 80, нулевая пауза — в 180 секунд, ослабленный порог
схожести — обратно в 0.6.

Отдельно проверяется детектор похожести: перефразировка того же ответа
другому автору должна блокироваться, а ответ по другой теме — проходить.
Это не украшение, а главная защита аккаунта: Threads блокирует именно за
похожие ответы разным людям.

Код возврата 1 означает, что какая-то защита не сработала. В этом случае
**мониторинг запускать нельзя** — покажите вывод разработчику.

### Состояние: что с аккаунтом сейчас

```bash
node lib/monitor/guardrails.mjs --состояние
```

Показывает, опущен ли стоп-кран (и почему), сколько ответов израсходовано
за сутки и когда можно следующий. Код возврата 1 — стоп-кран опущен.

### Снять стоп-кран

```bash
node lib/monitor/guardrails.mjs --снять-стоп-кран "перевыпустил токен"
```

Обоснование обязательно и короче 10 символов не принимается: оно уходит в
журнал, и через месяц по нему видно, почему работу возобновили. Сначала
**устраните причину**, потом снимайте.

⚠️ Если причина была похожа на блокировку действий — не снимайте в тот же
день. Подождите сутки, посмотрите в приложении, не пришло ли предупреждение
от площадки, и снизьте лимиты перед запуском.

## 5. `monitor/api.mjs` — проверка доступа

```bash
node lib/monitor/api.mjs
```

Три безобидных запроса на чтение: кто я, какие лимиты, контрольный поиск.
Ничего не публикует.

Главное, ради чего он есть — **невидимый отказ Threads**: без одобренного
скоупа `threads_keyword_search` поиск не выдаёт ошибку, он молча ищет
только по вашим собственным постам. От «ничего не нашлось» это не отличить.
Проверка ищет заведомо частое слово и смотрит, есть ли в выдаче чужие
посты. Если все найденные посты ваши — скоуп не одобрен, и мониторинг
работать не будет.

Коды возврата: 0 — доступ есть, 1 — доступ не работает или неполон,
2 — токена нет вовсе.

## Про файл `.env`

Токен живёт в `.env` в корне репозитория. Node сам такие файлы не читает,
поэтому `lib/env.mjs` подгружает его при старте `api.mjs` и `monitor.mjs`.

Переменная, заданная в терминале руками, всегда главнее файла. Отсутствие
`.env` не ошибка: токен можно задать и обычной переменной окружения.
